# QCL 启动器

> **要可运行的程序**：[Release v1.0.0](https://github.com/hujiao233/kcstudio-QCL/releases/tag/v1.0.0)
> 下载 `QCL-1.0.0-portable-win64.zip`，解压后双击 `QCL.exe` 即可，无需安装 Python 与依赖。
>
> **本仓库的 `qcl/` 源码不可直接运行**（逆向反编译产物）：43 个模块中 36 个无法被
> Python 解析；即便能解析的，也有大量表达式在反编译中丢失（实测约 850 处）。
> 仅供阅读实现思路，不能当作可运行代码。详见文末「源码状态」。

一个为 Minecraft 玩家做的启动器：实时同步官方版本、Mod/光影/资源包/数据包/插件 一键下载、
每个版本完全隔离、内置虚拟网联机、「我在自己电脑上发布新版本，别人自动收到更新提示」的自动更新，
外加一个**能一句话帮你配好整合包、并能联网查资料回答问题的 AI 助手**。

## 主要能力

| 能力 | 说明 |
| --- | --- |
| **AI 助手** | 见下方专章：一句话生成实例（挑版本/加载器/Mod 并自动装好）、带联网检索的 Minecraft 问答 |
| 版本同步 | 直接读取 Mojang 官方版本清单（`piston-meta`），官网一出新版本就能立即看到并下载，支持正式版 / 快照 / 预览版 |
| 加载器 | 一键安装 **Fabric / Forge / NeoForge / Quilt**，自动选择最新可用版本，版本清单同样实时拉取 |
| Java | 自动检测本机 Java，缺失时按 MC 版本自动下载对应版本（1.18+ 用 17，1.20.5+ 用 21） |
| 内容中心 | Mod / 光影 / 资源包 / 数据包 / 插件 全部支持，来源 Modrinth（免 Key）与 CurseForge（填 Key 后可用），自动下载必需依赖 |
| 版本隔离 | 每个实例都是独立的 `mods / shaderpacks / resourcepacks / datapacks / saves`，互不干扰 |
| 联机 | 登录启动器账号 → 输入对方用户名即可加入对方的「虚拟网」世界，跨网络通过主机中转；另含局域网自动发现与直连服务器列表 |
| 社区 | 内置论坛（发帖 / 回复）与实时聊天室，数据挂在主机上：自己开主机就是自己当服主，大家连同一个主机地址就是同一个社区 |
| 自动更新 | 你在自己电脑上「发布新版本」后，只要你的主机在线，别人的客户端启动/定时检查时就会弹出更新提示，点击即可更新 |
| 卸载 | 在 cmd 里输入 `remove QCL`，按提示确认后会删除所有 QCL 文件，**保留 .minecraft 存档目录** |

## 目录结构

```
桌面\QCL\                  ← 程序目录（可整体移动）
  QCL.exe                  ← 主程序
  remove.cmd               ← 提供 remove QCL 命令
  _internal\               ← 运行库
  data\                    ← 配置 / 日志 / 缓存 / Java / 服务端数据
  updates\                 ← 你发布的更新包（发布者才有）
桌面\.minecraft\            ← 游戏目录（默认，设置里可改）
  versions\                ← 原版与各加载器的版本文件
  libraries\               ← 共享库
  assets\                  ← 资源
  instances\<实例>\         ← 每个实例独立：mods/ 光影/ 资源包/ 数据包/ 存档/ 配置
```

## 安装（发布给别人用）

用 `dist_setup\QCL-Setup-<版本>.exe` 这一支单文件安装程序，双击即可：

- 选安装位置（默认 `%LOCALAPPDATA%\Programs\QCL`，不需要管理员权限）
- 可选：创建桌面快捷方式 / 添加到开始菜单 / 装完直接启动
- 自动在「应用和功能」里登记，卸载会清干净程序、快捷方式和注册记录，
  但**桌面上的 `.minecraft`（存档、Mod、光影）不动**

升级时直接再跑一次安装包覆盖即可。它只覆盖程序文件，
不会碰安装目录下的 `data\`（那是你的设置和联机数据）。

自己构建安装包：

```bat
build.bat                     :: 先打主程序到 dist\QCL
python tools\make_setup.py    :: 再打安装包到 dist_setup\
python tools\t_setup.py       :: 装一遍再卸一遍，验证闭环
```

> 安装程序支持静默安装，方便批量部署：
> `QCL-Setup-1.0.0.exe --silent --dir=D:\QCL --no-shortcuts --no-run`；
> 卸载同理加 `--yes`。

## 使用方法

### 1. 第一次启动
双击 `QCL.exe`。首次启动会自动：

- 把程序目录加入用户 PATH（这样 cmd 里才能用 `remove QCL`）
- 创建桌面/开始菜单快捷方式
- 在系统「应用和功能」里注册卸载项（卸载命令就是 `remove QCL`）

### 2. 登录游戏账号
首页右上角 → 支持三种方式：

- **离线登录**：填个名字即可，单机/局域网可用
- **微软账号**：需要在 Azure 注册一个应用，把 Client ID 填进设置（公用客户端 + 重定向 `http://localhost`）
- **外置登录**：填外置登录地址（如 `https://littleskin.cn/api/yggdrasil`）后登录

### 3. 创建实例并装 Mod
1. 「游戏版本」页选择 MC 版本 → 选加载器 → **创建实例并下载游戏文件**
2. 「内容中心」页切到 Mod/光影/资源包/数据包/插件 → 搜索 → 点「安装」（依赖会自动带上）
3. 回首页点「启动游戏」

### 4. 联机

**先决条件**：至少要有一台电脑当主机。你自己这台要当主机的话，
先到「设置」勾上 **「这台电脑就是主机」** 并重启启动器（会起本地服务，HTTP 25800 / 中继 25801）。
别人那边则到「设置」把主机地址填成 `http://你的IP:25800`。

1. 「联机」页注册并登录 QCL 账号（账号保存在主机上）
2. 双方互为好友（输入对方用户名添加，对方在「处理好友请求」里接受）
3. **房主**：点「开启联机房间」→ 启动游戏 → 进入存档 → 游戏内点「对局域网开放」
   → 启动器自动识别端口，房间就绪
   （若没自动识别，把游戏里显示的端口号手动填进去再点「使用此端口」）
4. **加入的人**：输入房主的用户名 → 点「加入」→ 启动器会自动复制 `127.0.0.1:25565`
   → 在游戏里「直接连接」粘贴该地址即可

> 跨网络时数据会经过主机转发，所以只有主机在线才能联机。
> 同一网络下可以直接用「局域网」页签，那里会自动列出开放到局域网的世界。
> 提示没看懂时看提示条：连不上主机、密码错误、对方还没开房间，都会有明确文字说明。

### 5. 社区（论坛 + 聊天）

侧边栏「社区」页，两个页签：

- **论坛**：发帖问问题、分享整合包，别人可以在帖子下回复
- **聊天室**：实时聊天，3 秒自动拉新消息，自己发的消息会立刻出现

用之前需要先在「联机」页注册并登录账号 —— 帖子和消息都记在账号上，匿名不能发言。

数据存在**主机**那一侧（和联机、自动更新共用同一台服务端），
所以：自己开主机就是自己当服主；把主机地址填成别人的，连进去的就是别人的社区。
聊天只保留最近 500 条，帖子保留最近 100 条，存在主机程序目录的 `data/server_data.json` 里。

## 自动更新（发布者看这里）

1. 在这台电脑上打开 QCL → 设置 → 勾上 **「这台电脑就是主机」**（会启动本地服务，默认 HTTP 25800 / 中继 25801）
2. 别人那边：设置 → 主机地址填 `http://你的IP:25800`（有域名写域名）
3. 你开发/打包出新版本后：设置 → **发布新版本** → 填版本号（如 `1.0.1`）和更新说明
   → 程序会把当前目录打包成 zip 并写入 `updates\manifest.json`
4. 客户端启动或每 10 分钟检查一次，发现更新就弹窗提示，点「立即更新」会自动下载、关闭后替换并重启

> 你的主机需要在路由器上转发 25800（HTTP）和 25801（联机中继）端口，客户端才能连上。

也可以用命令行常驻运行服务端（无界面）：

```
QCL.exe --server --api-port 25800 --relay-port 25801
```

## remove 命令

```
C:\> remove QCL

   ============================================================
     QCL 启动器 卸载程序
   ============================================================

   是否要删除QCL启动器？（Y是/N否）

请输入 Y 或 N 后回车: Y

   正在准备卸载，请稍候...

   [1/6] 删除程序文件...
   ...
   QCL 启动器已卸载完成。
   你的存档目录已保留：C:\Users\admin\Desktop\.minecraft
```

输入 `N` 则提示「已取消，未删除任何文件。」，不做任何改动。

输入 `Y` 后会删除：程序目录全部内容、`%APPDATA%\QCL`、`%LOCALAPPDATA%\QCL`、
桌面与开始菜单快捷方式、卸载注册项、PATH 中的 remove 命令。
**`.minecraft`（存档）目录会完整保留**——它默认在桌面，不在程序目录里，
所以卸载后你的世界、Mod、光影都还在，重新安装 QCL 即可继续玩。

## AI 助手

侧边栏「✦ AI 助手」页，两个模式。

### 一句话生成实例

输入「低配电脑想让游戏流畅一点」「想玩机械动力那种大型科技自动化」之类的大白话，
QCL 会自动出一套方案：实例名、MC 版本、加载器、建议内存，以及一份**经过校验的 Mod 清单**。
勾选后点「一键创建实例并安装」，就会创建实例、安装加载器、下载 Mod 和游戏本体。

关键在于清单保真。**AI 负责发散，Modrinth 负责保真**：

- 本地有一份方案库（性能优化 / 大型科技 / 魔法冒险 / 探索冒险 / 建筑创造 / 生存辅助），
  离线也能出方案
- 检测到 AI 时，让 AI 补充点子并润色命名与简介
- **每一个 Mod 都要拿去 Modrinth 校验**：确认存在、且有适配当前 MC 版本与加载器的版本。
  AI 补充的 Mod 走严格模式（只认精确 slug），避免模型编造出一个名字后被模糊搜索
  "贴心地"匹配到某个不相干的 Mod 上
- 找不到的会列到「未找到」区并写明原因（如「暂无适配 1.20.1 + Forge 的版本」），不会混进安装列表

有个贴心设计：如果某个 Mod 在当前版本下大面积不可用，会自动换一个 Mod 生态更成熟的版本重试。

### 问一句

问版本更新内容、Mod 用法、报错排查。回答时**先联网检索再作答**，并把参考链接列在答案下面。

检索这块踩过不少坑，最后的做法是"先找权威条目，再让搜索引擎补"：

- **问到具体版本**（"1.21 更新了什么"）→ 直接去读该版本的官方 wiki 条目，
  不问搜索引擎。版本条目页信息最全也最准，一步到位
- **问到游戏机制**（"末影龙怎么打"）→ 把中文术语换成英文（末影龙 → Ender Dragon），
  直接检索英文 wiki 的条目名。中文 Minecraft Wiki 已经停止维护、接口返回空，
  能查到的权威资料基本都是英文的
- **问到具体 Mod / 加载器**（"JEI 怎么用"）→ 用英文名走通用搜索

另外两个实测结论，写在代码注释里免得以后又被"优化"掉：

- Bing 只要查询里带 `Minecraft` 这个词，就不再返回网页结果，而是吐一堆固定的
  「Minecraft 实体卡片」（官网 / 应用商店 / 百度百科 / 网易官网）。
  所以查询里一律去掉这个词，并有一层过滤器识别丢弃这类结果
- 把中文长问句整句丢给搜索引擎，命中率极低（它做的是关键词匹配，不是阅读理解）。
  长句会先压成关键词再搜

### AI 从哪来

设置页「AI 助手」卡片会自动检测，优先级：

1. **本机 Ollama** —— 检测到正在运行就直接用它：不出网、免费、不上传任何游戏数据
2. **云端接口** —— 没检测到 Ollama 时，在设置里填 OpenAI 格式的地址 + Key + 模型名
   （DeepSeek / 通义 / 豆包 / OpenAI 都通用）
3. 两者都没有，或者手动关掉 AI —— 「一句话生成实例」依然可用，走内置方案库

卡片上有「重新检测」和「测试连接」，可以直接验证是否配好。

> **默认优先用本机的 qwen 系列模型**。模型不是越大越好：同一台机器上
> qwen2.5 的中文理解与 Minecraft 术语准确度明显好于 1.5B 级小模型。
> DeepSeek-R1 蒸馏类模型会把正文写进「思考过程」字段，导致读不到回答内容，
> 程序会自动把它排到最后并换一个模型重试。

## 常见问题

**Q：装 NeoForge 报 "There is no minecraft launcher profile"？**
这是 Forge/NeoForge 安装器的老规矩：它要求游戏目录里有官方启动器的
`launcher_profiles.json` 才会开工，而 QCL 自建目录从来不会生成它。
现在装之前会自动补一个占位文件（已存在则原样不动，不影响你真装过官方启动器）。

**Q：点「启动游戏」弹一个只有 OverflowError 的报错？**
已经在 1.0.0 之后修掉了。这个报错跟游戏本身没关系，是启动器把一个超出 Qt 32 位整数的
退出码塞进信号里导致的。同一个版本修掉的还有三处：log4j 配置路径要写成 `file://` URL、
0 字节的库文件不能被当成"已下载"（否则会报缺少某个类）、新版 MC 的原生库 jar 必须进 classpath。

**Q：游戏一启动就崩，日志里是 `Failed to locate library: lwjgl.dll`？**
新版 MC 的原生库 dll 在 jar 里是嵌套路径，只靠 `-Djava.library.path` 找不到，
必须把 natives jar 也放进 classpath —— 现在的版本已经这么做了。

**Q：NeoForge 装到一半刷屏 "Connect timed out"？**
安装器把 Maven 地址写死在 `maven.neoforged.net`，国内经常整段连不上。
程序会在失败后用国内镜像把这些依赖预先放进 `libraries` 再重跑，
正常网络下几轮内能装完。若镜像也拿不到，建议挂代理后重试，或改用 Fabric。

**Q：下载很慢 / 连不上 Mojang？**
设置 → 镜像源 选「BMCLAPI（国内加速）」。程序在任一地址失败时会自动回落其他源。

**Q：CurseForge 搜不到？**
CurseForge 需要 API Key，去 console.curseforge.com 申请后填到设置里；没填时会自动用 Modrinth。

**Q：想换游戏目录？**
设置 → 游戏目录 → 浏览/直接填路径 → 应用。默认在 `桌面\.minecraft`。

**Q：Mod 装到哪个实例了？**
装到「内容中心」页左上角选中的实例里，每个实例的 Mod 互不影响。

## 从源码构建

```bat
build.bat
```

产物：`dist\QCL\QCL.exe` + `_internal\` 共约 **76 MB**（已剔除软件 OpenGL 与用不到的 Qt 模块），
打包成便携 zip 后约 **32 MB**。

依赖：`PySide6`、`requests`、`PyInstaller`（Python 3.13）。
构建脚本会生成图标、做源码静态检查、清理旧产物、打包到 `dist\QCL\QCL.exe`。

回归测试脚本：

| 脚本 | 作用 |
| --- | --- |
| `tools\check_static.py` | 静态检查（Thread 成员撞名 / 布局误用），`build.bat` 会自动调用 |
| `tools\smoke.py` | 构造主窗口并遍历所有页面，验证界面无崩溃 |
| `tools\test_ui.py` | 遍历点击六个页面的全部按钮 + 所有对话框，捕捉「点了没反应」 |
| `tools\test_login.py` | 首页与联机页登录按钮点击实测 |
| `tools\test_account.py` | 联机账号 API 闭环：注册 / 登录 / 好友 / 房间 |
| `tools\test_multiplayer.py` | 虚拟网全链路：房主隧道 → 客人按用户名接入 → 真实数据往返 |
| `tools\test_vnet_login.py` | 联机页 UI + 真实主机服务端联动 |
| `tools\test_exe_multiplayer.py` | 用打包好的 `QCL.exe --server` 跑联机全链路（最终验收） |
| `tools\test_remove.py` | 在 %TEMP% 搭假安装，验证 `remove QCL` 的三种场景 |
| `tools\test_real_remove.py` | 用真实 `dist\QCL` 复制品跑完整卸载 |
| `tools\make_icon.py` | 生成 `build\icon.ico` |
| `tools\encode_remove.py` | 把 `remove.cmd` 转码为控制台编码 + CRLF |

> **为什么需要这些测试**：PySide6 会静默吞掉槽函数里的异常，`--windowed` 打包后连
> stderr 都没有，界面出错的表现就是「点了没反应」。启动器内也内置了全局异常捕获，
> 任何界面异常都会弹提示并写入 `logs\error.log`。

> `remove.cmd` 有两个必须遵守的约束，否则中文会变成乱码或被当成命令：
> 一是换行必须是 **CRLF**，二是编码必须与控制台代码页一致（中文 Windows 为 GBK）。
> 启动器每次启动都会自动转码并修复程序目录里的 `remove.cmd`，无需手工处理。

## 源码状态（重要）

本仓库的 qcl/ 目录是从发行包字节码**反编译**得到的，供阅读实现思路，
**不是可运行代码**。问题有两个层面：

| 层面 | 现状 | 能否自动检出 |
| --- | --- | --- |
| 语法 | 43 个模块中 36 个无法被 Python 解析 | 能（编译即报错） |
| 语义 | 约 850 处表达式/语句体在反编译中丢失 | **不能**，静默出错 |

语义退化比语法错误更隐蔽：它语法合法、导入不报错，只会让程序行为不对。

| 模式 | 数量 | 例子 |
| --- | --- | --- |
| 丢失的语句体 | 495 | `if not x:` 后面只剩 `pass`，原分支体没了 |
| 空字典常量 `{ }` | 135 | `data = { }` 原本是 `data = manifest(force)` |
| 丢失的 `or` 回退 | 100 | `if not v:` 紧跟裸 `v`，原本是 `v = v or '0'` |
| 裸表达式语句 | 120 | 一行只剩一个名字，原意的取值/调用丢失 |

> 统计口径：`pass` / `continue` 是合法关键字，不一律算伪影，只把紧跟在
> 复合语句头之后、块内仅剩 `pass` 的情形计入"丢失的语句体"。

统计方式：`python tools/degrade_survey.py`（随本提交加入）。

因此**不要用这里的源码做二次开发或行为推断**。需要依据时，请对照
[`bytecode/`](bytecode/README.md) 里的真实字节码。

判定方式：

\\at
python tools\check_syntax.py --root . --python313 <python3.13>
\
根因是反编译器（pycdc）对 CPython 3.11+ 的两项机制支持不全：

| 机制 | 表现 | 状态 |
| --- | --- | --- |
| 零成本异常（异常表） | 	ry/except 缩进错乱、块范围吞掉后续代码 | **已修复** |
| PEP 709 内联推导式 | , []、\(lambda .0: ...)\、\.0continue\ 残片 | 待解 |

零成本异常的修复已随 	ools/pycdc_python313.patch 提交，改了三处：
异常表项 stack_depth == 0 的判定在 3.11+ 永不成立（depth 已含解释器压入的
异常对象，实测 	ry/except 为 1），放宽为 <= 1；END_FOR 的额外出栈只对
3.12 生效，改为 >= 3.12；try 块结束位置误用 handler 偏移 entry.target，
改用 entry.end_offset。

的便携包（31.7 MB，解压即用）。
